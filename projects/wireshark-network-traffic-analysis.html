01

Objective

The objective of this project was to strengthen practical network analysis skills by capturing traffic and examining how different protocols behave at packet level.

Rather than treating Wireshark as only a packet viewer, the project focused on understanding conversations between hosts, protocol fields, connection establishment, encrypted traffic indicators and how packet evidence can support security investigations.

02

Analysis Environment

Wireshark Linux TCP/IP ARP TCP UDP TLS QUIC Display Filters Packet Inspection

Traffic was captured and reviewed in a controlled environment where network activity could be generated and analyzed without inspecting third-party communications.

03

Methodology

  1. Traffic Capture

    Selected the appropriate network interface and captured traffic generated during controlled network activity.

  2. Traffic Reduction

    Used Wireshark display filters to isolate protocols and reduce unrelated packets from the analysis view.

  3. Protocol Inspection

    Expanded packet layers and reviewed addressing, ports, flags, protocol fields and other relevant metadata.

  4. Conversation Correlation

    Related individual packets to the larger communication flow between endpoints.

  5. Behavior Interpretation

    Compared observed packet behavior with expected protocol operation to understand what the traffic represented.

  6. Documentation

    Recorded observations and translated packet-level evidence into understandable network-security findings.

04

Protocol Analysis

PROTO-01

ARP — Local Address Resolution

ANALYSIS

Reviewed ARP request and reply traffic to understand how systems on a local network associate IPv4 addresses with MAC addresses.

OBSERVED

Broadcast requests identifying a target IPv4 address followed by responses containing the corresponding hardware address.

SECURITY RELEVANCE

Understanding normal ARP behavior provides a foundation for recognizing suspicious address-resolution activity and investigating local network anomalies.

PROTO-02

TCP — Connection-Oriented Communication

ANALYSIS

Examined TCP conversations to identify connection establishment, source and destination ports, sequence information and TCP flags.

OBSERVED

Packet sequences showing the establishment and continuation of stateful communications between endpoints.

SECURITY RELEVANCE

TCP analysis helps identify service connections, unexpected destinations, failed connection patterns and unusual session behavior.

PROTO-03

UDP — Connectionless Traffic

ANALYSIS

Reviewed UDP datagrams and compared their behavior with connection-oriented TCP communications.

OBSERVED

Lightweight datagrams containing source and destination port information without a TCP-style connection handshake.

SECURITY RELEVANCE

UDP traffic analysis is useful when investigating services that do not establish traditional TCP sessions and when identifying unexpected datagram activity.

PROTO-04

TLS — Encrypted Application Traffic

ANALYSIS

Examined encrypted TLS traffic to distinguish visible connection metadata from application content protected by encryption.

OBSERVED

TLS-related records and encrypted application data where the packet payload was not directly readable as normal plaintext.

SECURITY RELEVANCE

Even when content is encrypted, endpoint, timing, protocol and connection metadata can remain valuable during network investigations.

PROTO-05

QUIC — Modern Encrypted Transport

ANALYSIS

Identified QUIC traffic and reviewed how modern web communication can operate differently from traditional TLS-over-TCP traffic.

OBSERVED

QUIC traffic transported over UDP, demonstrating why analysts should not assume modern encrypted web activity will always appear as conventional TCP-based HTTPS sessions.

SECURITY RELEVANCE

Familiarity with QUIC helps analysts correctly interpret modern browser and application traffic during packet investigations.

07

Security Value

  • Packet analysis can confirm what systems are actually communicating across a network.
  • Protocol knowledge makes it easier to distinguish normal network behavior from activity requiring further investigation.
  • Network metadata remains valuable even when application payloads are encrypted.
  • Display filters allow large captures to be reduced to relevant traffic efficiently.
  • Packet-level evidence can support incident investigation, troubleshooting and penetration-testing observations.
08

Lessons Learned

  • Understanding TCP/IP fundamentals significantly improves Wireshark analysis.
  • Individual packets make more sense when interpreted as part of a complete conversation.
  • Source and destination addresses, ports and protocol fields provide important context during investigations.
  • Encryption changes what an analyst can inspect, but it does not make all network activity invisible.
  • Modern protocols such as QUIC require analysts to understand traffic beyond traditional TCP-based web communications.
