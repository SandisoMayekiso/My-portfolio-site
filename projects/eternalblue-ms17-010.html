01

Objective

The objective was to practise a structured Windows network penetration-testing workflow by identifying an SMB-exposed host, determining whether it was affected by MS17-010 and validating the risk only inside a deliberately vulnerable training environment.

The exercise emphasized disciplined enumeration, vulnerability verification, impact analysis and remediation guidance.

02

Lab Environment

Kali Linux Windows Target VMware Nmap SMB MS17-010 Metasploit Framework

The attacker and target systems were hosted in a private virtual network. Testing was limited to systems intentionally configured for training.

03

Methodology

  1. Host Discovery

    Identified the Windows target inside the isolated lab network.

  2. Port Scanning

    Enumerated reachable TCP services and identified SMB-related exposure.

  3. SMB Enumeration

    Reviewed SMB service information and gathered enough context to determine whether further vulnerability assessment was justified.

  4. Vulnerability Assessment

    Assessed the target for indicators associated with the MS17-010 vulnerability rather than assuming exposure based only on the presence of SMB.

  5. Controlled Validation

    Confirmed the security impact inside the authorized lab without extending testing beyond the target required to demonstrate the risk.

  6. Post-Validation Review

    Verified that successful exploitation could lead to severe host compromise and documented the affected attack surface.

  7. Reporting

    Recorded the finding, likely impact, remediation actions and lessons learned.

04

Finding

WIN-001

SMB Service Vulnerable to MS17-010

CRITICAL

The lab target exposed SMB and was confirmed to be affected by MS17-010, a critical Windows vulnerability associated with remote code execution risk on unpatched systems.

ATTACK SURFACE

The Windows host exposed SMB services to the attacker's network segment.

IMPACT

Successful exploitation can result in unauthorized code execution, host compromise and potential lateral movement opportunities in a real network.

ROOT CAUSE

Missing security updates left the operating system vulnerable to a known critical SMB flaw.

REMEDIATION

Apply the relevant Microsoft security updates, remove unsupported operating systems, restrict SMB exposure and maintain regular vulnerability and patch-management processes.

07

Remediation

  • Apply Microsoft security updates addressing MS17-010.
  • Remove or upgrade unsupported Windows systems.
  • Restrict SMB access to only trusted systems and network segments.
  • Disable unnecessary SMB services and legacy protocols.
  • Use internal firewalls and segmentation to reduce lateral movement.
  • Maintain continuous vulnerability scanning and patch verification.
  • Monitor SMB-related events and unusual lateral network activity.
08

Lessons Learned

  • Service exposure must be assessed in context; SMB alone does not prove vulnerability.
  • Patch management remains one of the most important controls against known critical vulnerabilities.
  • Windows network enumeration is a core part of identifying real attack paths.
  • Critical vulnerabilities should be validated carefully and only within authorized scope.
  • Reporting should connect the technical issue to likely operational impact and practical remediation.
