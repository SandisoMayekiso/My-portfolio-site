WEB APPLICATION SECURITY

Web Application Security Testing Lab

A deliberately vulnerable Flask and SQLite application used to practise controlled SQL injection and cross-site scripting testing, request inspection and remediation-oriented reporting.

ROLE Security Tester / Developer
ENVIRONMENT Local Controlled Lab
STATUS Completed
$ methodology Build → Proxy → Test → Validate → Remediate
01

Objective

Build a small web application that could be safely tested for common input-handling weaknesses without targeting a third-party system.

The project focused on understanding how unsanitized input and unsafe database-query patterns can create exploitable application behaviour, while also practising the reporting and remediation side of web security testing.

02

Lab Environment

Kali Linux Burp Suite Python Flask SQLite Jinja2 Browser DevTools
03

Methodology

  1. Application Review

    Reviewed the application's input points, authentication flow, database interactions and rendered output.

  2. Request Inspection

    Routed requests through Burp Suite to inspect parameters, headers and server responses.

  3. Controlled Input Testing

    Tested lab inputs for unsafe SQL construction and unescaped client-visible content within the deliberately vulnerable environment.

  4. Validation

    Confirmed observable application behaviour and documented the affected input paths.

  5. Remediation Review

    Compared vulnerable patterns with safer parameterized queries, output encoding and input-handling practices.

04

Findings

WEB-001

Unsafe SQL Query Construction

HIGH

The vulnerable lab intentionally included a database interaction pattern where user-controlled values could influence query logic. This was used to demonstrate why concatenating user input into SQL statements is unsafe.

IMPACT

In a real application, unsafe query construction can expose data, bypass intended application logic or affect database integrity depending on permissions and query context.

REMEDIATION

Use parameterized queries or prepared statements, apply appropriate authorization checks and avoid dynamically constructing SQL from untrusted input.

WEB-002

Unsafe HTML Output Handling

MEDIUM

The lab included intentionally unsafe rendering behaviour to demonstrate how user-controlled content can become executable browser content when escaping and output handling are bypassed.

IMPACT

Cross-site scripting can allow attacker-controlled script execution within a victim's browser context and may affect sessions, page content or user trust.

REMEDIATION

Preserve framework auto-escaping, use context-aware output encoding and avoid marking untrusted content as safe HTML.

06

Lessons Learned

  • Vulnerability testing is more valuable when the underlying code path is understood.
  • Burp Suite is useful not only for payload testing but for understanding application request flow.
  • Parameterized SQL and safe output handling directly address entire classes of common web vulnerabilities.
  • A useful pentest deliverable should explain impact and remediation, not just show that a weakness exists.
