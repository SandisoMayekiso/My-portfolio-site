01

Objective

The objective of this lab was to practise a structured penetration testing workflow against an intentionally vulnerable Linux target. The exercise focused on discovering the target, identifying exposed network services, enumerating FTP and investigating whether the detected software version was associated with a known vulnerability.

The environment was intentionally created for security training. Testing was restricted to the isolated lab system.

02

Lab Environment

Kali Linux Metasploitable 2 VMware Nmap FTP vsFTPd 2.3.4 Metasploit Framework Linux

Kali Linux was used as the testing system and Metasploitable 2 as the deliberately vulnerable target. Both virtual machines were kept inside a controlled lab network.

03

Methodology

  1. Host Discovery

    Identified the target system within the isolated laboratory network before performing service enumeration.

  2. Port & Service Scanning

    Used Nmap to identify listening TCP services and gather service/version information from the target.

  3. FTP Enumeration

    Investigated the FTP service exposed on TCP port 21 and identified the server software as vsFTPd 2.3.4.

  4. Vulnerability Research

    Compared the identified service and version against known vulnerability information and available security-testing references.

  5. Controlled Validation

    Validated the known vulnerable service only against the intentionally vulnerable Metasploitable 2 target within the isolated environment.

  6. Post-Validation Review

    Reviewed the resulting access and gathered only the minimum information required to confirm successful validation before ending the test.

  7. Reporting

    Documented the affected service, security impact, evidence, remediation guidance and lessons learned.

04

Finding

NET-001

Vulnerable vsFTPd 2.3.4 Service

CRITICAL

Service enumeration identified vsFTPd 2.3.4 running on the target FTP service. The intentionally vulnerable Metasploitable 2 image contains the compromised release commonly used to demonstrate the historical vsFTPd 2.3.4 backdoor vulnerability.

ATTACK SURFACE

TCP port 21 exposed an outdated FTP service that disclosed enough version information to support vulnerability research.

IMPACT

A vulnerable backdoored service may allow unauthorized remote command execution and can lead to complete compromise of the affected host.

ROOT CAUSE

Use of a known compromised and obsolete version of the FTP server software.

REMEDIATION

Remove the affected version, install software only from trusted sources, verify package integrity, patch unsupported services and restrict unnecessary network exposure.

07

Remediation

  • Remove vulnerable or unsupported versions of vsFTPd.
  • Obtain server packages only from trusted repositories and validated distribution channels.
  • Verify package integrity where checksums or signed packages are available.
  • Disable FTP when the service is not required.
  • Restrict management and file-transfer services using network segmentation and firewall rules.
  • Maintain asset and software inventories so outdated services can be identified and remediated.
  • Perform routine vulnerability scanning and patch management.
08

Lessons Learned

  • Accurate service-version detection can significantly narrow vulnerability research.
  • An open port alone is not necessarily a vulnerability; the service, configuration and software version must be investigated.
  • Enumeration should come before exploitation.
  • Known vulnerabilities should be validated carefully rather than assumed solely from a version string.
  • Successful penetration testing includes remediation guidance and business impact, not only technical exploitation.
  • Controlled labs provide a safe environment for developing repeatable penetration-testing methodology.
